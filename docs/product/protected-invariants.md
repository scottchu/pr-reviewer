# Protected product invariants

This register defines what a bounded change must preserve. It does not declare the entire product accepted. “Protected” means later work must keep the behavior unless the user explicitly changes it; accepted corrections revise the relevant durable specification before derived code. Known defects remain defects, even where earlier tests passed. A visible violation cannot be waived by a mechanical PASS.

Detailed contracts remain in [file workspace](pr-file-tree-first.md), [canvas reading](review-loop/canvas-reading.md), [panels](review-loop/canvas-panels.md), [Story and exploration](review-loop/story-and-exploration.md), [runtime](review-loop/runtime.md) and [ontology](project-repository-ontology.md). This is their preservation/status index, not a second implementation specification.

## Change and review boundary

Every slice/handoff must name: accepted change; exact allowed seams; protected rows of this register; any explicit supersession; preservation checks; and delivered, pending or unverified status. A real defect may require a narrow exception, but chat or code cannot silently authorize a redesign. Record the reason and updated contract before implementing that exception.

A reviewer checks the authorized delta AND the affected protected behavior. Check actual glyphs, node/label/route ownership, gestures and return states where the change affects them; DOM presence, counts and bounding boxes alone do not establish readability. Keep failures and classify evidence honestly. Do not reopen unrelated protected areas merely to improve a probe.
