# Configured tests on a pinned head

**Date:** 2026-10-24

**Contract revision:** `head-test-v1`, proposed design for independent plan review.

**Accepted intent:** Run a useful configured check on a retained snapshot's pinned head, keep discussion usable, inspect the same attributed result through React and the owner CLI, and retain honest cancellation/restart uncertainty.

**Implementation status:** Not implemented or execution-qualified by this document. The source/environment/owned-process qualifications below are prerequisites, not evidence of success.

**Parents:** [Review loop](README.md), [shared owner and semantic recovery](semantic-storage.md), [import jobs](import-jobs.md), [story and exploration](story-and-exploration.md), [reactive ownership](../reactive-design.md).

## User experience and supported trust

The reviewer selects a named available target for the currently inspected retained snapshot and chooses Run. The request captures that snapshot permanently; later history navigation does not retarget it. Show the target's purpose, pinned head and availability reason before submission. Show queued, preparing, running, stopping and terminal outcome as distinct states. A saved request is never a pass. Jobs remain inspectable in that snapshot's test history even after the current review head advances.

The result summary states Passed, Tests failed, Cancelled, Timed out, Unavailable, Execution error or Outcome unknown, with an attributed reason and link to bounded plain output. Expand evidence to inspect the exact source/head/tree, target revision and argument vector, relative cwd, runtime/dependency/environment identities, observed exit and artifact completeness. Do not crowd the primary flow with process-journal fields. A test pass establishes only this target's execution result; source references classified as tests, authored claims and graph coverage do not establish execution or whole-PR correctness.

While a job runs or is unknown, source navigation, saved anchored questions, replies and story/exploration continue through their existing owners. Requesting a run does not select another source, rewrite a draft, move the story cursor, start analysis, publish a clarification or wake an agent. The application owns the selected job and exact receipt readback; React presents it and delegates intent. Cancelling a job is explicit. Closing the panel or browser stops observation, not the process.

This first target is for the trusted local `github.com/scottchu/pr-reviewer` source project only, using owner-reviewed fixed target definitions and local objects. Import permission for another repository is not execution permission. This is not an OS sandbox: minimal environment, isolated copies and reviewed targets do not kernel-deny network or arbitrary filesystem access, provide hard CPU/RSS caps, or prove complete descendant enumeration. Targets requiring network, credentials, native sessions, installation or external writes are unavailable under this contract. Unknown trust or effects blocks target qualification rather than silently widening it.

## Complete source and isolated existing environment

The review's `Snapshot.sources` is a bounded reading manifest, not an executable project. A private owner source-location resolver must obtain an already admitted matching import whose applied admission receipt names this exact review/snapshot and whose full candidate equals the retained snapshot candidate. Alternatively the owner composition may supply a prequalified local locator bound to that exact repository/head; public requests never accept a path. Neither route rediscoveries a newer head or calls RequestAnalysis to borrow its internal locator logic.

Materialize a complete owned execution tree from locally present immutable Git objects under a private external job root, using raw commit/tree/blob reads with the existing acquisition protections: no lazy fetch, replace objects, inherited Git overrides, external helpers/textconv, hooks, fsmonitor or filter execution. Do not use ordinary checkout, `git worktree add` checkout, `git archive` export substitution, or the live checkout contents. This execution tree is the isolated worktree for the run; it deliberately has no linked `.git` metadata and does not need Git inside the source-core tests.

Verify the requested object is the exact commit, retain its root tree ID, enumerate the entire tree and validate every path, mode, object type, size and byte hash before activation. V1 accepts regular files mode100644/100755 only; reject submodules, symlinks, invalid UTF-8/nonportable paths, absolute/traversal paths, case/normalization collisions on the destination filesystem, `.git` components and tracked `node_modules` overlays. Reject executable-affecting repository config (`.npmrc`, Bun configuration, version-manager configuration and dotenv files), and filter-dependent material rather than running configuration/helpers to repair it. Raw `.gitattributes` never authorizes transforms; unsupported required filters make the target unavailable. Reject missing objects without network fallback. Write with exclusive/no-follow owned-path semantics and preserve declared executable modes. Never modify the source repository or its indexes/configuration.

The source manifest contains schema version, repository identity, headSha, tree ID and sorted complete entries `{path, mode, objectId, bytes, sha256}`. Record its digest, source byte/file counts and full package.json/bun.lock hashes. Immediately before spawn verify the materialized tree against it; capture tracked-content differences and an untracked/overlay inventory after termination. Expected overlays are only owned dependency, HOME, temp/cache and evidence directories. Preserve mutation evidence before cleanup. Changed tracked source or unexplained overlays prevent a clean pinned-head pass, even if the child exited zero; they produce an execution error with actual exit retained.

Dependency material comes from an explicitly owner-designated existing installation. There is no install, fetch, lifecycle execution or writable shared link. Copy only the complete required package trees into this job's node_modules and retain a sorted path/mode/byte/content manifest and digest. V1 rejects dependency symlinks, external links, special files and missing package trees; source and dependency symlinks are unsupported rather than recursively followed. Generated caches are real private job directories. Snapshot/verify source and destination hashes before and after the copy; concurrent mutation of the donor fails qualification. A donor lock/package name alone is not installed-content provenance.

The accepted metadata compatibility rule is exact bun.lock bytes plus equality of canonical **entire package.json after removing only `scripts`**. Retain both full manifest hashes, the non-script canonical digest, lock hash and exact changed script keys. Script-only drift is allowed because no package script/lifecycle is run; record the reviewed difference explicitly. Any other difference, missing metadata or required script behavior is `environment_unavailable`. Target qualification also traces the pinned test files and their local/package imports for the declared no-network/no-product-runner behavior; an unchanged filename or script vector alone cannot qualify newly changed executable code. Independently compare installed package manifests/versions and their complete contents to the recorded owner-approved closure, including the alias mapping. Record donor provenance and the validated copied closure identity. This establishes a precisely attributed existing environment, not proof that a historical package-manager install was reproducible or supply-chain verified.

Construct the environment from an allowlist: `LANG=C`, `LC_ALL=C`, `TZ=UTC`, `CI=1`, `NO_COLOR=1`, task-owned `HOME`, `TMPDIR`, cache directories and a fixed runtime-only PATH. Do not inherit bearer credentials, cloud/model/provider tokens, native participant variables, any `REVIEW_*` variable, `NODE_OPTIONS`, preload/module paths, runtime option variables or user/Git/package configuration. The runtime may require additional benign platform values only after explicit qualification and a versioned environment-policy amendment. Persist only safe declared values, with private root paths represented by owned-root roles in public evidence; never snapshot the inherited environment. No credential is passed to the child.

Source and closure preparation is a bounded owned effect under the same lease as execution. It is not background prefetch or installation. Qualification failure retains its reason and no test launch. Source copying and hashing can fail or be slow; these bounds are policy values requiring actual tests, not performance measurements.

## Public values and authority

All IDs are nonempty bounded strings of at most128 characters, revisions nonnegative integers, object/content hashes validated against their algorithm, and all public inputs strict (unknown fields reject). Authenticated user commands use the existing ingress/short transaction owner. Test receipts occupy the existing global command collision domain, including review, import, analysis and story receipts; reserve `test-result:` for private result admission. Check current authorization before replay as well as before mutation. Same command/actor/canonical payload returns the original receipt; changed payload/actor or cross-family ID reuse is `command_conflict`.

| Public operation | Contract |
|---|---|
| Configured targets | Authorized reviewId/snapshotId → bounded registry summaries with targetId/revision/digest, vector/cwd/policy summaries and `available`, `qualification_required` or `unavailable` plus reason. This read never creates an execution tree or launches a process. Availability metadata cannot substitute for the fresh pre-spawn checks. |
| RequestTest | commandId, reviewId, snapshotId, targetId, expectedTargetRevision. User only; capture exact retained repository/source/head, definition and active credential reference, then atomically create queued job and receipt. No path, shell, argv, cwd, environment, URL, executable or side override. |
| CancelTest | commandId, jobId, expectedJobRevision. User only; current owner authorization and exact job CAS. Queued cancel prevents claim; active cancel records intent. Stale CAS is `test_job_conflict`. |
| Test jobs | Authorized reviewId/snapshotId, optional exact jobId and minimumJobRevision. Return bounded summaries and selected exact job/result. A minimum requires exact jobId; wrong scope or unmet minimum is an explicit rejection. Paginate with stable opaque cursor, at most32 summaries per page. Reading history never spawns. |
| Test artifact | Authorized reviewId/snapshotId/jobId/artifactId → immutable manifest and bounded plain bytes, optionally bounded offset/length within the known artifact. No raw path or URL. |
| Owner CLI | `request`, `status`, `result`, `cancel` send these same strict gateway operations; return exact job/receipt/result identities as JSON. Read the existing restrictive owner credential reference internally; never print it, take it as visible argv or open SQLite/start a runner. |

Use POST `/api/commands` for test commands and authenticated read-only POST `/api/tests/targets`, `/api/tests/jobs`, `/api/tests/artifact` for strict query bodies. Attached agents may query only jobs/artifacts in their existing authorized review and attachment generation through these public gateway reads; bootstrap credentials have no access. There is no new MCP execution tool or participant wake in this slice. An agent's read authority is never execution authority. Revoke/fence late results and reads at every owner/credential boundary; an already observed child exit is retained privately even when public admission is denied.

Receipts return commandId, actorId, reviewId, snapshotId, jobId, jobRevision, state applied/rejected and typed result/error. Job revision is independent of review/story/context/analysis/graph revisions. Confirm the exact receipt job and retained source; a newer job cannot satisfy an older command's readback. New explicit request IDs intentionally create additional runs, never supersede earlier jobs. UI remount, safe polling and exact receipt retries cannot create another invocation.

Private storage ports expose a nonserialized TestOwner/TestGrant for claim, requested/start/exit observations, cancellation/limit lookup, outcome admission and quiescence reconciliation. Bind them to shared epoch, owner generation, job/invocation, phase, captured source and target definition. Check authority before every observation/effect lookup/release, not only terminal admission. Import/Analysis grants, serialized JSON, worker text or a successful exit cannot mint TestGrant. Store-owned result admission checks current authorization and cancellation/CAS after expensive verification outside the transaction.

Identity composition is explicit: jobId and invocationId are fresh owner-generated opaque IDs; sourceManifestId and closureManifestId are their versioned canonical manifest digests. The environment manifest binds schema version, target definition digest, sourceManifestId, closureManifestId, both package manifests, lock identity, resolved runtime content/version, platform/architecture, safe environment values with owned-root roles and effective limits; environmentId is its digest. A result body binds schema version, exact job/invocation/review/snapshot/head/target/environment IDs, observed start/exit, outcome/reason, quiescence, source/dependency mutation account, output completeness and the ordered artifact manifests. resultId is SHA-256 of that canonical body, excluding its own ID. Generated file locations, bearer data and mutable display labels never supply an identity. Retain the validated manifests, not only hashes that cannot later explain the run.

A retained job includes schema version, captured intent and credential reference (never bearer), jobRevision, created/updated times, captured definition, source/environment manifest IDs, invocation and phase observations, cancellation intent, structured outcome and immutable artifact references. Public projection removes credential reference, source locator, raw root paths and host process identities; safe evidence still contains exact source/target/runtime/content digests. Owner-only process journal retains requested/start/exit timestamps, ordinal, executable role, PID/start/group identity, exit code/signal and bounded reason. Logs are untrusted plain output, never protocol authority or executable markup.

## One lease, durable process ownership and recovery

Extend the existing `execution_lease` occupant kind to `test` and the same startup unresolved scan to test jobs/invocations. One current store epoch owns import, semantic and test effects. An atomic claim persists preparation invocation and slot together; it never holds a database transaction across filesystem/process work. Missing lease rows cannot hide unfinished test invocations. Queued tests do not block comments; unknown test occupancy blocks new import/analysis/test effects until justified quiescence. No second scheduler/database owner or test-only lease is introduced.

Preparation and run belong to one job invocation with explicit phase `prepare` then `execute`. The lease remains held across that boundary. Persist every Git/runtime process request before spawn; record the actual start separately. Each requested process has at most one spawn attempt; ordinals are contiguous and only one root process is active at a time. Preparation may use at most32 fixed Git reads, preferably bounded batch reads, plus one qualified runtime-version observation; execution permits exactly one test-root launch. A root may spawn children; one invocation does not imply one OS process. Do not reuse acquisition's git/gh/glab command type as arbitrary test authority or decode test output as the semantic worker protocol.

| State | Evidence and transition |
|---|---|
| queued | Durable accepted intent; no claimed effect. Cancel commits cancelled with no launch. |
| preparing | Atomically claimed invocation/lease; verify source, target, runtime and closure. Unsupported/missing input → unavailable if definitively no live effect; I/O/verification faults → error. |
| running | Preparation witness and durable test launch request precede observed process start. UI differentiates launch requested from observed running. |
| cancel_requested | Accepted cancellation prevents further launches/admission. Request verified owned termination; this state is not stopped. |
| passed | Observed exit0, complete validated bounded result/artifacts, unchanged pinned source and qualified environment, confirmed owned-group quiescence, no earlier cancel/limit/fault, atomic owner admission. |
| failed | Observed nonzero normal test exit, valid environment/preparation and bounded evidence, confirmed quiescence, no overriding cancel/limit/infrastructure fault. Means test command failed; do not infer a specific failed assertion unless bounded output supports it. |
| cancelled / timed_out | Accepted cancel or elapsed deadline, respectively, and confirmed owned termination; retain any actual exit and partial evidence. |
| unavailable / error | Required input unsupported/missing versus infrastructure/spawn/result/storage/validation failure. `output_limit`, `source_mutated`, `environment_mutated`, `artifact_invalid` remain typed error reasons, not assertion failures. |
| unknown | Launch, exit, result acknowledgement or owned descendant state cannot be established. Retain original invocation/evidence; no automatic retry or new invocation. |

Admission races are serialized. If cancel commits before terminal admission, a later exit0 cannot become passed; if terminal admission wins first, cancel returns already_terminal without rewriting evidence. Limit/fault intent similarly dominates a success exit. Failed assertion/command, unavailable environment and uncertain launch remain separate even when no usable log exists.

Normal stop uses the actual owned child handle plus verified process-group/start identity. Use the existing bounded TERM, 250ms eligibility recheck, then KILL where ownership still verifies, with a further700ms settlement observation. Signal delivery alone, parent exit, pipe closure, elapsed deadline or an old PID being absent does not prove all owned descendants stopped. Never signal a reused/unverified PID/group. Uncertain descendants or inherited pipes leave unknown and keep the effect slot. Process group quiescence is the supported observation, not a claim of exhaustive OS containment.

On restart, unclaimed queued work may be claimed once. A claimed prepare/execute invocation without a definitive committed outcome becomes unknown, including requested-before-spawn/ack gaps. Never blind rerun the target or rematerialize under a fresh invocation. Definitive owned absence/quiescence may release the shared slot, but the old job stays unknown with `quiescence=confirmed` when outcome was lost. New explicit user intent is needed to run again. Unlike existing import/analysis lifecycle labels, test reconciliation does not convert an unobserved test outcome to a failed assertion. Lease eligibility must distinguish unresolved effects from retained outcome uncertainty; update all shared scans consistently so a quiescent unknown history does not block forever.

Publish artifacts atomically under owner-generated IDs, then commit a validated reference/result using stable private admission identity. A published orphan without a committed job result is quarantined, not adopted as success from its contents. If the owner can read the exact already committed receipt/result after a lost acknowledgement, return it without effects; otherwise preserve unknown/evidence error and reconcile quiescence. Missing/corrupt referenced output changes its read availability to `artifact_unavailable`/`artifact_invalid`, never reruns or silently rewrites the historical observed exit. No result can be reported passed before its entire manifest and references commit together.

## Bounds and artifact handling

| Bound | Initial v1 policy |
|---|---|
| Shared execution | One import/analysis/test invocation; at most8 pending test jobs across this owner, including unresolved occupancy; reject ninth before creating receipt/job/effect |
| Source tree | At most8192 regular files, 8MiB per blob, 64MiB total bytes; complete tree or unavailable, no partial executable tree |
| Dependency closure | At most32768 regular files, 32MiB per file, 64MiB total copied bytes; initial two-package closure fits observed metadata only, not an executed qualification |
| Deadline | 120s total prepare+execute from claim; preparation at most30s within it; monotonic runtime timing, durable wall timestamps for evidence, never restart the clock after a phase |
| Output | 1MiB combined stdout/stderr bytes in observed arrival order, preserving channel/chunk ordinal; overflow stops the process and retains an explicitly incomplete bounded prefix |
| Result artifacts | 2MiB total encoded UTF-8 result/manifest/output per job; 64MiB retained test evidence per review, separately from source/semantic budgets |
| Queue/history metadata | 256 retained test jobs per review in v1; reject new jobs at cap, preserve old records; no silent eviction/compaction |
| Public reads | At most32 summaries per page; at most64KiB artifact bytes per read; all encoded command/query envelopes retain existing8MiB ceiling |

Reserve worst-case2MiB evidence quota atomically on request, count pending reservations plus retained bytes, convert to actual retained bytes on final admission and release unused reservation only with an atomic disposition. Unknown jobs retain their reservation until a supported reconciliation commits a bounded record; never publish a half-result/pass because quota ran out. Failed requests cannot leave orphan reservations. Lower test-only injected limits may exercise boundaries; production callers cannot enlarge them.

Artifacts are only stdout/stderr bounded records and an owner-produced evidence manifest; do not recursively upload arbitrary child files or HTML/JUnit paths. Runtime-generated unexpected files appear in the overlay account, not automatically as trusted artifacts. IDs bind job/invocation/schema/hash/size. Reject traversal, symlink substitution, wrong identity/size/hash and over-limit reads. Output is rendered as inert text with no shell/link execution or HTML interpretation. The trusted target must not emit credentials; environment exclusion is not a guarantee that arbitrary repository code cannot find secrets elsewhere.

Keep active/unknown execution trees and owner records for recovery. After confirmed quiescence and committed durable evidence, the owner may remove only that exact job's disposable source/dependency/temp copies; retained artifacts and manifest identities remain readable without the checkout. Cleanup failure is bounded diagnostic evidence, never permission to delete another tree or rerun. Shutdown requests stop for import, analysis and test owners before awaiting all actual active promises; no-op wakes retain the running promise. Gateway lifetime owns the runner, independent of React/CLI subscribers.

## Integration and observable acceptance

Add managed routes `test-request-committed-to-owner`, `verified-test-outcome-to-admission` and `test-job-committed-to-authorized-view`. Registration scope, authorization, bounded polling, epoch/credential/lifetime fences and disposal follow the existing registry; cursor means route publication, never job revision or test success. Diagnostics show sanitized disposition, bounded latest/active job summaries and real committed revisions without tokens, locators or arbitrary error strings. Workspace startup remains review login → analysis login → story hydration; test reads join only after exact review authorization and cannot delay or change that ownership sequence.

The test application bridge captures review/snapshot and credential generation for request/read/cancel, preserves exact pending command identity, and confirms receipt against exact job. A transport loss leaves an explicit unknown request/recovery action; safe readback or exact command retry may reconcile it but never create a fresh ID automatically. Logout/disposal fences late publication. Existing review-question write-ahead and draft/frame semantics remain under their current owner; the test bridge cannot clear or repurpose their recovery storage.

Required behavior is measurable: exact target run from React on a complete pinned source with qualified environment; one durable job/invocation despite retries/remount; same result identity through actual CLI HTTP; an anchored question accepted while a real process is active; actual zero/nonzero/cancel/timeout/unknown distinctions; process/source/environment/artifact limits; import/analysis/test exclusion and independent discussion; restart readback without launch; immutable history and no participant wake. Real controlled fixtures establish negative and timing-sensitive cases. Actual own-PR use separately establishes the production target journey; a naturally passing fast target is not a fabricated failing or actively cancelled own-PR run. Graph-first comprehension and visual critique remain independent acceptance, as do native/human and deployment evidence.
