# Viewport-driven graph presentation

Status: adopted bounded implementation. Date: 2026-10-28.

## Reader outcome and scope

Readers must be able to pan, zoom, inspect source and move existing graph items without preparing and mounting every offscreen detail for each interaction. Preserve the existing source-comparison account, exact evidence, semantic colors, file ordering/indentation, document groups, test lane, camera and gesture ownership. This presentation optimization does not change extraction, ontology, comparison or admission policy. The [source pipeline](source-pipeline.md) remains authoritative for those responsibilities.

The initial delivery adds an independently testable scene index, a real dedicated browser worker, bounded viewport scheduling, conservative rendering selection, incremental preparation and on-demand source-reading work. Aggregate zoom summaries, GPU rendering, remote spatial storage and arbitrary-repository intake remain later design choices; do not introduce them merely to demonstrate performance. Existing zoom levels continue to expose the same content.

## Responsibilities and inputs

UI owns camera, CSS-pixel viewport size, device-pixel ratio, native input/focus, live drag feedback and DOM measurements. Camera movement must not wait for a worker, rerun extraction or trigger global layout. Experience Service owns comparison/disclosure intentions. UI Projection owns presentation content; renderer inputs and state use named UI Types.

A scene query worker owns only deterministic spatial selection over a supplied UI geometry snapshot. The integration boundary manages worker creation, scoped messages, replacement, failure and teardown. No direct cross-subsystem subscription, new reactive library or generic worker framework is needed. Its wire messages contain serializable UI data, never GraphSessionUI callback closures or Domain objects.

Each geometry replacement has comparison and layout identity. Viewport queries carry request identity, camera translation/zoom, viewport width/height and pixel ratio; CSS pixels determine world bounds, pixel ratio determines raster quality only. Reject nonfinite/invalid geometry. Results are scoped to the active scene and latest applicable request. A late result cannot revive an old comparison, geometry, disclosure or movement state.

## Spatial selection and lifecycle

Build a reusable spatial index when geometry changes, not on every viewport query. Query conservative world bounds including a screen-space overscan margin. Keep the current scene usable while a bounded latest-request scheduler prepares replacement; coalesce superseded input rather than allowing an unbounded message queue. Keep camera updates outside expensive React scene state updates. Retain stable references when membership/content do not change.

Select node rectangles, group ancestry, route bounds and edge-label rectangles separately. A curve crossing the viewport must remain available even when both endpoints are outside. Include required endpoint/ancestor metadata without forcing their full offscreen content to mount. Bounds may conservatively overselect; they must not miss visible strokes or labels. Pin focused, inspected and actively dragged items as required to preserve keyboard/input and native disclosure state. Ancestor coordinates and manual overrides remain authoritative.

The existing layout needs DOM dimensions. Preserve its cold-start measurement phase before enabling spatial rendering selection; do not position offscreen nodes with invented sizes or rebuild layout from the visible subset. Measurements remain cached across culling. The initial ReactFlow adapter retains lightweight wrappers and ports for every model node, with explicit cached dimensions when content is culled. It omits offscreen heavy entity content and relation DOM; it does not use `hidden=true` or ReactFlow endpoint-based visibility, which could suppress curves crossing the viewport with both endpoints outside. Wrapper count and membership application remain O(N), and this is not an O(visible) total-DOM claim. Source-open/close, file expansion and manual movement invalidate their affected scene geometry; pan/zoom alone does not invalidate layout. This initial measurement limit must be reported separately from steady-state improvements.

Layout takes the current authoritative full nodes, never the projected ReactFlow store nodes. The store may contain offscreen content-culling flags or semantic-filter visibility, focus and measurement-only state. Import only finite positive measured width/height by exact full-node ID; preserve authoritative data, styles, positions and interaction policy before layout. Reflow after viewport culling or semantic filtering must not persist render-only state into the full model. Excluded render content may measure invisibly/inertly, but the measured render clone itself is never adopted as a layout node.

On worker startup/error/timeout/unsupported environment, retain the full existing renderer as a correctness fallback and release worker resources. Scene replacement and unmount dispose prior subscriptions, listeners and pending work. Do not leave stale visibility hiding newly changed or moved content. Rapid camera movement outside a result's coverage must retain a safe presentation until a valid replacement is ready.

## Incremental and demand-driven work

Reuse projected content by immutable entity/evidence identity; disclosure changes must not remap every unrelated entity. Use comparison-lifetime immutable-identity caches for entity/relation presentation and defer source-reading projection until its UI property is consumed. Prepare full source-reading views only when requested, retain exact witnesses and preserve close/reopen behavior. Closed native details must not mount all hunk rows. Keep preview rows and existing document summaries available as needed by the unchanged UI. Cache within the comparison lifetime, bound retained working state, and discard obsolete scene indexes.

Distinguish download/parse, projection, layout/routing, worker query and DOM rendering costs. Keeping the canonical prepared corpus resident is permitted in this initial slice and is an explicit loading limit; lazy DOM or projection is not proof of reduced network bytes. Later source-asset partitioning must preserve evidence hashes and get its own delivery acceptance.

## Correctness and performance evidence

Independently authored tests compare indexed queries with a brute-force geometric oracle over negative coordinates, nested parents, zero/large zoom, resizes, outside endpoints/crossing curves, labels, overscan boundaries and invalid inputs. Exercise serializable worker messages, scene replacement, out-of-order responses, coalescing, timeout/failure, disposal and safe fallback. Verify source rows, disclosures, pinning, manual positions and domain graph remain unchanged.

Record a repeatable synthetic benchmark at increasing scene sizes plus the pinned PR25 corpus. Report index construction, query time, candidates visited, selected elements and transport size separately. Use operation-count/scaling checks for regression acceptance; machine-specific timings are descriptive. No FPS, device smoothness or browser memory claim follows from Node timing. A spatial query should avoid scanning the complete separated scene when only a small region is visible.

Actual React checks cover desktop/touch pan/zoom, viewport resize, edge/label crossing, source open/close, Show/More/Hide, focus and movement retention, worker fallback and unchanged camera. Supported-host unavailability is UNRUN, not PASS; existing deployment authorization does not convert asset readback into journey evidence.

## Initial implementation decisions and verified limits

The dedicated module worker builds an immutable bounding-volume tree over node rectangles, conservative quadratic control hulls and independent measured label rectangles. Split on the longest axis by median; bounded leaves keep at most eight items. Queries use inclusive rectangle intersection. Screen-space overscan is 240 CSS pixels and route hulls include 16 world units for strokes/markers. Device-pixel ratio does not change world selection. Endpoint IDs and ancestor IDs are returned separately from heavy-content membership.

`SceneSnapshotUI` carries comparison/revision identity, absolute node bounds/parent IDs and route endpoint/bounds/label data. `ViewportQueryUI` carries that identity, a monotonic request, camera/size/pixel ratio/overscan and node/route pins. `SceneSelectionUI` returns scoped membership, coverage and separate leaf-item/branch-bounds operation counts. These are serializable presentation contracts. `GraphSessionUI` exposes the qualified comparison ID; canonical Domain objects and UI callbacks never enter worker messages.

The integration owner permits one in-flight replacement or query, keeps only the latest desired scene/query, and waits for matching acknowledgements. Results must match the sent request and current scene/latest request. Retain a prior selection only while its coverage contains the current viewport and all current pins. Geometry replacement, movement or unfinished layout suspends selection and immediately restores full rendering. Unsupported construction, transport error, worker error, deserialization failure and a 2000 ms timeout terminate the worker and leave full rendering for that mount. Unmount removes listeners, cancels timers and terminates the worker. No background retry system is introduced.

Open outer source readers, inner all-hunk readers and unpaired-source readers retain their DOM while offscreen, preserving native disclosure and reader scroll. Current focus and inspection are unioned into membership on the main thread, including when a prior response arrives; active movement uses full rendering until new geometry is ready. Source previews/witnesses retain exact content. Closed readers mount their summary, and materialize their body only after opening. Lazy unmount must preserve close/reopen state independently of offscreen pinning: retain native inner disclosure flags and both scroll axes of removed/added preview panes and full-hunk readers in a UI-owned comparison-lifetime cache keyed by entity and reader kind. Closing an outer source reader does not close its inner reader. Restore saved open/scroll state in the mounting layout phase, before presentation; capture scroll continuously, before native close activation and at visible unmount. A hidden native ancestor can report zero scroll; ignore such cleanup reads instead of overwriting the last visible position. Cache only known comparison entities and the fixed reader kinds, and discard it with the comparison mount. Never retain source-row DOM merely to remember these small values. Presentation caches live with immutable comparison/entity identities and preserve unaffected UI references; source-reading panes materialize on first consumption and are reused on reopen. Full source data still resides in the canonical payload.

Local evidence: the owning pure suite covers the frozen canonical/default/20/40/Hide projection oracle, brute-force spatial comparisons, worker transport/lifecycle, pin union and lazy/stable presentation. The production build emits a separate worker asset. Dedicated-thread Node execution validates the actual worker entry; it does not establish browser scheduling or React correctness. Authored React regressions cover desktop/touch camera input, source/Show/More/Hide, resize, focus/manual retention, a real-corpus curve with endpoints outside and worker fallback. Their execution is still UNRUN while the supported browser host is unavailable. Independent comprehension and exact-main deployment remain separate delivery gates.

Scaling evidence uses 1k/10k/50k separated nodes with 100 queries. At 50k, the index examines 600 leaf items and 2700 branch bounds total versus 5,000,000 baseline brute-force item checks. Index construction and full scene transport are separate costs (about 3.48 MB serialized at 50k). Real-corpus projection uses 3751 entities, 210 default nodes and 253 relations; geometry benchmarking uses fixed synthetic dimensions, never measured browser geometry. Full initial DOM/label measurement, O(N) lightweight wrappers/ports and membership application, global layout/routing on geometry changes, and the fully resident main asset remain explicit limits. Timings are descriptive Node observations; no FPS, device-smoothness, browser-memory or network reduction has been established.
