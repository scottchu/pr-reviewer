## Durable lessons for the integration owner

1. A query with explicit historical analysisId applies minimumJobRevision to that historical chosen job. Confirm a new preparation job's receipt without that historical filter, then independently refresh the private historical facts. Otherwise a legitimate held analysis can make newer receipt confirmation fail or accidentally retarget its view.
2. Module and function anchors may share side/path/line ranges. Accessible controls need function kind/name context as well as coordinates; line-only labels can be ambiguous despite correct source identity.
3. Source inspection and graph focus are independent of legacy question composition. Retain exact context identities and offsets; the old LF-only lineCount cannot stand in for semantic parser coordinates.
4. Bound body excerpt loading to one background batch. Committed polling must not multiply slow source reads; explicit evidence navigation retains its own request ownership.
5. Record initial graph visibility and an actual child observation separately from proven overlap. Readable question commit plus the same still-live verified process after commit and subsequent exit establishes the bounded overlap.

These lessons are sent to the core/root owner for durable product-doc promotion; this new page is the UI owner's only documentation write scope.
